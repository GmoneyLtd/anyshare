# 代码规范与工作流程规则

## 1. 语言与标点规范

- 所有与用户的交流输出使用中文
- 禁止在代码、日志和注释中使用中文标点符号（如"，"、"。"、"："、"；"、"？"、"！"等）

**示例**:
```python
# 正确的日志写法
logger.info(f"Processing file {filename}, status: {status}")  # 使用英文标点

# 错误的日志写法
logger.info(f"处理文件 {filename}，状态：{status}")  # 使用中文标点
```
## 2. 代码规范
严格遵循ruff代码规范，修改代码前必须先查看全局配置文件(~/.config/ruff/ruff.toml)
主要关注点包括：命名规范、导入顺序、代码格式化、行长度限制、注释风格等
优先保证代码简洁易懂，不要过度设计，简单实用为主
注意控制圈复杂度，函数应尽量小且可复用
避免重复代码，提高代码复用率
改动前，做最小化修改，尽量不修改其他模块的代码

## 3. 代码解释与实现
解释代码时，使用简单易懂的语言，避免专业术语，最好配有图表说明
实现功能时，需要给出原理和执行步骤，最好有图表辅助说明
改动或解释前，必须查看所有相关代码，不能忽略任何一行代码
改动后，提供至少2个测试案例及其预期结果

## 4. Bug修复流程
遇到Bug时，必须遵循以下步骤：

理解问题 (Understand): 仔细阅读Bug描述和相关代码，复述对问题的理解
分析原因 (Analyze): 提出至少两种可能的根本原因
制定计划 (Plan): 描述如何验证这些原因，并给出修复方案
请求确认 (Confirm): 在动手修改前，向用户确认计划
执行修复 (Execute): 实施修复
审查 (Review): 检查修改是否有问题
解释说明 (Explain): 解释做了哪些修改以及原因

## 5. 规则优先级
代码功能正确性
代码简洁易懂
符合ruff规范
使用英文标点
最小化修改

## 6. 代码修改后的自检清单
[ ] 代码是否实现了预期功能？
[ ] 代码是否简洁易懂？
[ ] 是否符合ruff规范？
[ ] 日志和注释是否使用了英文标点？
[ ] 函数是否足够小且可复用？
[ ] 是否避免了重复代码？
[ ] 是否提供了至少2个测试案例？
